Claude Code: Code Mode e controles de permissão

O que muda quando o Claude escreve JavaScript para chamar as ferramentas, como ligar com segurança, como auditar o código e como a organização bloqueia.

01Contexto

Normalmente o Claude Code pede uma ferramenta por vez (Bash, Read, Edit…), lê o resultado e decide o próximo passo. No Code Mode, lançado na v2.1.323 (publicada em 12/11/2026, 19:12 BRT), o Claude escreve um trecho de JavaScript que faz várias chamadas de ferramenta de uma vez, e o Claude Code executa esse código na sua sessão.

Na conversa você vê as chamadas (por exemplo, o diff da edição), não o código. Para ler o código, pressione Ctrl+O e expanda a linha Code no visualizador de transcrição.

Experimental e desligado por padrão

Pode mudar ou ser removido em qualquer versão. Trate como laboratório, não como padrão do time.

02Por que importa

  • Menos ida e volta em tarefas com muitas chamadas relacionadas: a mesma mudança em vários arquivos, buscas cujo resultado precisa ser filtrado e comandos independentes rodando em paralelo.
  • Muda o modelo de controle: no auto mode, o classificador revisa o código e não cada chamada. Quem administra o Claude Code precisa saber disso antes que alguém ligue.
  • A mesma versão endureceu permissões: a 2.1.323 traz dezenas de correções em regras Bash, sandbox e login de MCP. Atualizar é recomendado mesmo sem usar o Code Mode.

04Passo a passo

Confira a versão

No canal stable, a 2.1.323 pode demorar a chegar. Espere ou mude para latest.

Confirme e verifique

Na primeira vez, escolha Yes, turn on Code Mode. Depois do restart, a sessão mostra:

Se aparecer Code Mode (experimental) isn't available, o motivo vem na mesma linha e também em /status.

Dê uma tarefa com muitas chamadas e leia o código

Pressione Ctrl+O, expanda a linha Code e leia o JavaScript. Pressione Ctrl+O de novo para voltar.

Entenda como as permissões se aplicam

  • Cada chamada feita pelo código passa pelas suas regras deny e ask e pelos hooks PreToolUse. Não precisa mudar regra nem matcher de Bash.
  • Auto mode: o classificador revisa cada trecho de código antes de rodar, não cada chamada, e não vê valores calculados em execução (ex.: um caminho tirado de uma busca). Para o que você precisa controlar, mantenha regras ou hooks.
  • Demais modos (Manual, acceptEdits etc.): o código começa sem revisão e você é perguntado em cada chamada que já pediria permissão nesse modo.
  • Lembre a precedência: deny → ask → allow. A primeira regra que casa decide, e um allow não abre exceção num deny.

Audite o código com um hook REPL

A ferramenta que executa o código do Claude se chama REPL, e o JavaScript chega em tool_input.code. Este hook só registra o código e não bloqueia nada:

Hook lento = chamada recusada

Se um hook PreToolUse falha ou estoura o tempo numa chamada vinda do código, a chamada é recusada (the hook failed / the hook did not finish). Mantenha o hook rápido ou use "onFailure": "continue" quando fizer sentido.

Desligue ou bloqueie para a organização

Para você: remova a variável do shell e do ~/.claude/settings.json, ou coloque "0". Um 0 em qualquer lugar vence um 1 no outro.

Para a organização: coloque "0" nas managed settings. Abaixo, um exemplo que também bloqueia leituras sensíveis e o modo bypass (chaves documentadas):

SistemaCaminho do arquivo
macOS/Library/Application Support/ClaudeCode/managed-settings.json
Linux / WSL/etc/claude-code/managed-settings.json
WindowsC:\Program Files\ClaudeCode\managed-settings.json

Confirme com /status: a linha Setting sources mostra Enterprise managed settings (file). Quem já está numa sessão com Code Mode continua até sair. Não dá para ligar o Code Mode para os usuários via managed settings.

05Armadilhas

Regras Bash casam texto, não intenção

O próprio aviso da doc: o Claude pode rodar um comando negado numa forma que a regra não pega, com ou sem Code Mode. Por exemplo, Bash(git push *) não pega git -C . push. Para limites reais, use o sandbox.

Auto mode não vê valores de execução

O classificador aprova o código olhando o texto. Se o caminho ou o comando sai de uma busca, ele não sabe o valor final.

Sessão "presa" ao Code Mode

Para claude --continue ou --resume, mantenha a variável em 1. Sessões iniciadas sem Code Mode retomam sem ele.

"Funciona na minha máquina"

Gateway, ANTHROPIC_BASE_URL customizada, Bedrock, apiKeyHelper, OpenTelemetry ligado ou DISABLE_TELEMETRY impedem o Code Mode de iniciar. Veja a tabela de motivos na doc.

Prompt com contagem regressiva

No auto mode, se um código novo começa enquanto o anterior roda, o anterior perde a revisão do classificador e você recebe um prompt com contagem regressiva. Sem resposta, a chamada é recusada.

06Boas práticas e segurança

  • Atualize para 2.1.323+ mesmo sem usar Code Mode. Correções de permissão desta versão:
  • Regras allow com curinga colado, como Bash(ls*), podiam pular o prompt. Uma regra que nomeia variável, como Bash(NODE_ENV*), agora pergunta.
  • Regras deny e ask agora pegam comandos rodados via sudo, env e wrappers parecidos.
  • O sandbox do Bash podia se desligar durante a sessão (corrigido).
  • Write/Edit podiam escrever em caminho coberto por uma regra deny de Read (corrigido).
  • --permission-mode auto sem auto mode disponível agora inicia em Manual, que pergunta antes.
  • "Don't ask again" para um allow que parece conter segredo, ou que iria para um settings.local.json rastreado pelo git, vale só para a sessão.
  • claude -p e o Agent SDK agora param na inicialização se os settings que ligam o sandbox forem inválidos, em vez de rodar sem sandbox.
  • Aviso na inicialização para regras allow Bash com * no valor de uma variável, ex.: Bash(PORT=* npm run dev).
  • Camadas: regras deny/ask + hook PreToolUse (inclusive REPL) + sandbox para limitar arquivos e rede dos comandos de shell.
  • Política de time: comece com Code Mode bloqueado nas managed settings e libere para um grupo piloto em máquinas sem a política.
  • Nunca use bypassPermissions fora de container ou VM isolada. Ele pula prompts até para caminhos protegidos como .git e .claude.
  • Segredos: negue leitura de .env e pastas de segredo com Read(...). Lembre que permissões são aplicadas pelo Claude Code, não pelo modelo. Instruções no CLAUDE.md não bastam.

07Exercício prático (30 min)

Objetivo: ligar o Code Mode num projeto de teste, auditar o código gerado e provar que uma regra deny continua valendo.

  1. Num repositório de teste, adicione ao .claude/settings.json uma regra "deny": ["Bash(git push *)"] e o hook REPL do passo 6.
  2. Inicie com CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 claude e confirme a linha "Code Mode (experimental) is on".
  3. Peça: "liste os links quebrados nos arquivos Markdown e corrija os que apontam para arquivos renomeados".
  4. Abra Ctrl+O e compare o JavaScript da tela com o que foi gravado em ~/.claude/audit/code-mode.log.
  5. Peça para fazer push. Verifique que a chamada foi recusada pela regra deny.
  6. Saia, rode claude --resume sem a variável e observe a recusa. Depois retome com a variável.
  • Sei ligar e desligar o Code Mode e sei onde a organização o bloqueia.
  • Sei onde ver o código (Ctrl+O) e como auditá-lo (hook REPL).
  • Sei explicar o que muda no auto mode e por que o sandbox ainda é necessário.
Gabarito

5) Cada chamada feita pelo código passa pelas regras deny/ask, então git push origin main é recusado. Uma variação como git -C . push não casa com a regra. É por isso que a doc recomenda o sandbox. 6) Com Code Mode desligado, o Claude Code se recusa a retomar uma sessão iniciada com ele.
